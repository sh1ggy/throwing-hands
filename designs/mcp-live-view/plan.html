Two play modes, one game: the plan

Train the camera, then play in Hardware RPS (the printed hand) or Software RPS (a virtual robot on screen). Same game engine, same MCP tools, Claude Desktop as the host. Details in PLAN.md; screen drafts in the gallery.

A plan, not a design-doc change: the doc doesn't include the screens or the play modes. You decide what goes into it.

1 · Train, then one of two modes

before play

Train

python tools/train_ui.py
  • Train rock, paper, scissors, nothing (D9)
  • 30-throw test until ≥ 85 % (G2)
  • No Claude needed
  • Never runs alongside play: one serial port
the rig

Hardware RPS

server.py --hand real
  • The printed hand, LEDs, relay, ISD1820 voice
  • Real HuskyLens reads your throw
  • Claude Desktop drives it over MCP
  • Screens optional: the hand is the show
anywhere

Software RPS

server.py --hand sim
  • A virtual robot in the browser (to build)
  • Real HuskyLens reads you; --fake simulates it too
  • Same game, same MCP tools
  • Before the hand exists, or if it breaks

--hand auto (default) asks the XIAO: servo board answers → real, otherwise → sim. Laptop speech is opt-in (--speak).
